The logic of each stage

The user names one US-listed underlying. Tradecraft then works through four stages, one screen at a time, and the user decides at the end of each whether to go on. Each stage has a detailed manual with the full rules, in part 4; this part gives the reasoning and points to it. The research findings behind the design are in part 1.

1 · Liquidity gate

CODE ONLY

The gate answers one question before any research is done: are there contracts on this underlying that can actually be traded? It excludes; it never scores. A wide quoted spread is a cost the user pays on the way in and again on the way out, so a name whose contracts fail is not worth a thesis.

INThe option chain: live quotes in market hours (Cboe, or Tradier if Cboe does not answer), the daily snapshot otherwise.
OUTPASS or FAIL, the count of eligible contracts, and every contract screened out, by reason.
THE USER DECIDESContinue, adjust the criteria, override a fail, or stop.

The rules that matter

  • Five criteria, all adjustable for the request: maximum bid-ask spread (default 5% of the premium), minimum open interest (100), days to expiration (42 to 90), maximum distance from spot (10%), minimum premium ($0.20).
  • At least two contracts must clear the screen for a pass.
  • The user may override a fail, but only with a written rationale, and the override is written to the decision record. An invalid quote cannot be overridden. The system itself never proposes a contract that fails.
  • Three sources of option quotes, in order: Cboe (15 minutes delayed), then Tradier (real-time), then the latest daily snapshot. The change is automatic and the screen names the source that answered. Stages 3 and 4 follow the same order.
  • On the snapshot the result is provisional: outside market hours, or when neither live source answers, it is computed on the latest daily snapshot and marked as such on every later screen.

What it does not do

It shows no premiums, so that pricing cannot anchor the thesis that follows. It does not rank underlyings or contracts.

Full rules: Liquidity gate. Code: tradecraft/gate.py, tradecraft/stage1.py.

2 · Thesis

5 AGENTS MEASURED FIGURES AND CHECKS IN CODE

The thesis stage produces a research brief: a view (bullish, bearish or no view), the evidence it rests on, and the conditions that would prove it wrong. The agents gather and read; code measures, grades and decides what counts.

INFilings, earnings and estimates, news, dividend dates, the macro calendar, price history.
OUTA brief: the view, graded findings, invalidation criteria, measured statistics and a recommended horizon.
THE USER DECIDESAccept and freeze, reject, or, after a no view, enter a thesis of their own.

The rules that matter

  • No agent sets a figure. The base rate of a higher close, the typical realized move, the volatility state and the recommended horizon are computed in code from price history. The base rate is shown beside the view and is not moved by it.
  • A finding carries a direction only when the evidence states a comparison. Three kinds can: results against estimates (built in code from the two numbers), a guidance change (the analyst extracts the figures; code compares them), and a new event on a fixed list. Everything else is context: shown, and unable to start, support or cancel a view.
  • Grades are set in code from three tests on the cited evidence: primary source, recent, specific. Three passes is strong, two is moderate, otherwise weak.
  • Three outcomes, all proper results: a view; no view because the findings that carry a direction conflict; no view because nothing carries one. A failure is never shown as a no view.
  • The draft is checked in code before the user sees it. Every claim must cite stored evidence, every number must appear in what it cites, and the draft may state no probability and rest on no price-derived signal. A failing draft is returned to the Thesis agent once, then rejected.

What it does not do

The Thesis agent never sees an option price, an implied volatility or a market-implied probability. Price trend, momentum and chart levels are description only. Index instruments return no view by rule, because sector and macro evidence may qualify a view but may not start one.

Full rules: Thesis stage, and the decision record docs/decisions/2026-11-18-stage-2-anchored-bearings.md, which governs where the two differ. Code: tradecraft/stage2.py, agents.py, validation.py, figures.py, evidence.py.

3 · Market and contracts

CODE ONLY

With the thesis frozen, the system opens the option chain and builds strategies that express the view with defined risk. This stage uses no model. Choosing a contract is arithmetic on quotes and history, and a model would add variance without adding information.

INThe frozen thesis (view and horizon), the option chain (Cboe, then Tradier, then the snapshot), price history, the stage 1 criteria in force.
OUTUp to three candidates on the same measures, filtered and ranked; the first is the "best fit".
THE USER DECIDESThe ranking priority, the cost cap, the expiration, an optional maximum loss, and which candidate to take forward.

The rules that matter

  • Defined risk only. For a directional view: two spread shapes and one bought option. Strikes are placed by the typical realized move for the days to expiration, never by chart levels.
  • No failure screen while any source answers. If Cboe does not answer the chain comes from Tradier; if neither does, the stage is built on the latest snapshot and every figure is marked provisional. A failure is shown only when all three fail.
  • Every leg is an eligible contract. A single option must pass the bid-ask criterion; the legs of a spread are judged together, through the cost cap.
  • A cost cap the user controls: estimated slippage as a share of maximum loss, 5% by default, adjustable from 2% to 10%. A candidate over the cap is filtered out and shown with the reason.
  • Ranking is on the user's priority alone: fit to thesis, reward-to-risk, or lowest slippage. Nothing is ranked on gross richness.
  • The expiration defaults to the thesis horizon. Switching it amends the horizon, and the amendment is recorded.

What it does not do

It never calls the first-ranked candidate "recommended". It does not filter on earnings or ex-dividend dates; it shows them. It asks for no account size.

Full rules: Market and contracts, with the operator's build decisions in docs/decisions/2026-11-17-stage-3-contract-selection.md. Code: tradecraft/stage3.py.

4 · Challenge

23 CHECKS IN CODE 2 AGENTS

Before the user decides, the system challenges both the thesis and the chosen contract. Rules come first. The Critic is confined to what rules cannot do, argues both sides at the same length, and gives no verdict.

INThe frozen thesis with its evidence, the selected candidate and the ones not selected, fresh quotes (Cboe, then Tradier), the project's own research.
OUTOne screen: the Critic's judgement on the left, the fixed-rule checks on the right, and a readiness line.
THE USER DECIDESProceed, return to contracts, or stop. Nothing blocks.

The rules that matter

  • Twelve checks on the thesis and eleven on the contract. Each returns flagged, passed, not applicable or could not be checked. A check never reports "passed" for want of data.
  • The thesis is restated as a question by a fixed template. The Critic is not shown the original wording or told who wrote the thesis, and the check that records the thesis's origin is withheld from it.
  • Retrieval is from the project's own research only, searched both ways for each claim, at most three passages a side. There is no web search.
  • The Critic's output is checked in code. Every objection must cite a check, a claim or a passage that exists; every claim must be given a standing; the two cases have the same length limit; a verdict, a score or advice is refused. A failing answer is returned once, then rejected, and the screen shows the checks alone.
  • The readiness line is set by code and is about whether the inputs are still valid (a stale thesis, a price that has moved), not about whether the trade is good.

What it does not do

It does not veto. Flags are not counted into a rating. The Critic does no research of its own, and for the demo it runs on the same model family as the Thesis agent, which the screen states.

Full rules: Challenge, with the operator's build decisions in docs/decisions/2026-11-17-stage-4-challenge.md, which govern where the two differ. Code: tradecraft/stage4.py, research.py.
